K75 (0c45:8006) report descriptors, captured 2026-10-05 via usbipd-win
(busid 2-2) into WSL: `usbhid-dump -d 0c45:8006 -e descriptor`.

The composite is three HID interfaces, all interrupt-IN at 1 ms:

  if0  keyboard  EP 0x81  16B pkt   65-byte report desc  (boot kbd + LEDs)
  if1  media     EP 0x82  16B pkt  158-byte report desc  (see below)
  if2  vendor    EP 0x83   8B pkt   30-byte report desc  (64B IN + OUT + feat)

if0 is the stock boot-keyboard report descriptor (mod byte, reserved
byte, 5 LEDs out, 6-key array) — TinyUSB's TUD_HID_REPORT_DESC_KEYBOARD()
is the same layout.

if1 is a multi-collection interface, report IDs:
  ID 3  consumer control (16-bit usage)
  ID 2  system control (3 on/off: sleep/wake/power)
  ID 1  120-bit bitmap keyboard (NKRO-style, Fn layer)
  ID 6  mouse (5 buttons, X/Y/wheel rel)
  ID 5  vendor page 0xFFFF, 3 bytes IN

if2 (the command channel the clone rides) is already a vendor-defined
64-byte channel — usage page 0xFF13, no report ID:
  usage 2       64-byte Input   (device->host, interrupt IN)
  usage 3       64-byte Output  (host->device, SET_REPORT on EP0 —
                                 there is no OUT pipe on the real device)
  usage 0xFF00  64-byte Feature (GET/SET_REPORT on EP0)

So the clone can keep all three report descriptors byte-identical and the
3-pipe IN-only topology; host->device commands go over EP0 control, which
is how the vendor's own config software talks.
